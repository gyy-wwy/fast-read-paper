# 学术 PPT 制作（第七步·详细规范）

本文件是 `fast-read-paper` 第七步「制作学术 PPT」的完整规范。第七步按阶段推进，**严格分阶段、不能跳步**：

- **阶段一**：先出**文字执行稿**，交付后停在文字阶段，等用户确认。
- **阶段二**：用户确认执行稿后，再逐页重建**结构化 SVG**，并配合 PowerPoint 实测迭代。
- **附加交付（可选）**：演讲稿——基于已确认的页面内容，按页生成讲稿。

---

## 阶段一：文字执行稿

本阶段只交付文字执行稿，**不生成 HTML、SVG 或 PPTX**。用户确认执行稿后，才进入阶段二。

### 第一步：询问输入资料（可以没有）

1. **PPT 模板**
   - 文件名：
   - 允许参考的模板页：
   - 是否只参考这些页面的版式、标题区、页眉、页脚、配色、字体层级、页面边距和排版框架。
   - 是否复用模板原有的正文、图片、数据、结论或文献内容。

2. **补充论文**
   - 文名：
   - 重点读取的 Markdown 内容或 PDF 阅读器页码：
   - 用途：补充研究背景、方法说明或结果对比。

### 第二步：询问汇报需求

- 主题：
- 计划页数：
- 汇报对象：
- 我的研究方向：
- 是否需要衔接我们已有工作：

**页数分配原则**：如果用户指定了页数，按指定页数自行分配内容；如果没有指定，根据有依据的内容量和每页讲述时间，选择合适页数。**不要机械地把下文的内容类别一类分成一页。**

### 第三步：内容与排版素材池

根据论文实际内容和选定页数，**自行决定每页的主题、内容组合及先后顺序**。以下为可选内容，不要求每页全部包含，也不要求每项单独成页：

- 研究背景、应用场景与问题定义；
- 现有方法的局限，以及论文希望解决的核心问题；
- 研究创新点及其对应解决的问题；
- 研究方法、系统结构、实验方法与技术路线；
- 关键实验条件、模型参数和数据来源；
- 研究数据、结果图、性能对比及限制条件；
- 论文已有结论；
- 与我们已有工作的联系，以及对后续工作的建议。

**可参考的排版结构（候选，非强制）**：左图右文、上文下图、三栏对比、大图配结论框、双栏对比、三模块并列、中心图配两侧说明、卡片式分区、横向流程、上下两层流程、左右步骤递进、结果—意义—下一步等。

- 结合每页内容和指定模板页，选择合适版式；**不要在一页中堆叠多种结构，也不要让所有页面使用完全相同的排版。**
- 呈现创新点时，可用 2–3 个简短模块；呈现论文明确给出的流程时，可用 ①②③④ 标记关键步骤。**仅在适合该页内容时使用这些形式。**

### 第四步：每页执行稿必须包含

先给出整套汇报的**页数安排和逻辑主线**，再逐页写出以下 9 项：

1. 页面标题和一句核心结论。
2. 本页要回答的问题，以及它与前后页的衔接关系。
3. 可直接用于页面的详细科研文字；说明哪些内容适合放在页面上，哪些内容留给口头讲解。
4. 使用的论文原图：来源论文、PDF 阅读器页码、图号、图中需要保留的坐标轴、图例、实验条件和数据含义。
5. 必须呈现的关键数据及其原文依据；如有适用条件或限制，一并说明。
6. 具体排版方案：参考模板第几页；复用其中哪些标题、页眉、页脚、颜色、字体层级和布局元素；图片、文字、数据分别放在哪个区域；强调色用于突出什么。
7. 本页底部应标注的文献题名和 DOI。
8. 明确区分「论文已有结论」和「对我们工作的建议」：后者使用「可考虑」「建议验证」「后续可探索」等措辞，不写成论文结论。
9. 放在页面下方的汇报备注，包括讲解提醒或需要解释的专业术语。

此外，**单独列出图片使用清单**，注明：哪些 Markdown 图片可直接使用，哪些图片需要从指定 PDF 页码提取。

### 第五步：资料使用与核对要求（红线）

- 不检索其他论文，不自行寻找其他图片。
- 图片只使用指定论文原图或原始数据，不制作描述性插图。
- 不生成论文中没有的实验数据、参数或技术细节。
- 不把推测性解释、跨论文延伸或对我们工作的建议写成论文已有结论。
- 若模板没有页码、页眉或页脚，不自行虚构；可在不破坏模板框架的前提下补充必要的文献来源信息。
- 每页都要明确写出参考模板的具体页码和复用的版式元素，**不要只写「参考模板风格」**。
- 如果文件、指定 PDF 页码或核对某项数据所需的依据缺失，标为「待核对」，说明缺少什么；不猜测，不擅自扩大阅读范围。

**结束时**：一次性返回完整文字执行稿，末尾列出「待核对事项」，然后**停在文字阶段，等待用户确认**。

## 阶段二：逐页结构化 SVG 重建

在用户确定完文字执行稿后，根据确认的 HTML 和提供的 PPT 模板为基准，逐页重建结构化 SVG。**本阶段只交付 SVG，不生成 PPTX，也不要重新设计页面内容。**

> 协作说明：本阶段是**协作式**。AI 生成 SVG 并输出验收清单与操作步骤；「PowerPoint 实测」需要用户在 PowerPoint 里完成（插入 → 转换为形状 → 双态对比 → 导出预览），再把结果（截图/偏差）反馈给 AI；AI 据此修改 SVG 源并重测，如此迭代。

### 第 0 步：环境探测（进入阶段二先做）

不要等生成完全部页面才发现这台机器上不能自动化。进入阶段二**先探测一次**：

```powershell
$ppt  = New-Object -ComObject PowerPoint.Application
$pres = $ppt.Presentations.Add(-1)
$s    = $pres.Slides.AddSlide(1, $pres.SlideMaster.CustomLayouts.Item(7))
$s.Shapes.AddShape(1, 10, 10, 10, 10)                        # 基线：应成功
$s.Shapes.AddPicture("<任意小 PNG>", 0, -1, 10, 10, 20, 20)  # 关键：能否插入图片
```

- 两者都成功 → 可尝试自动化插入与复核。
- `AddPicture` 报 `E_FAIL` 或进程崩溃 → **立即停止自动化尝试**，转为「AI 出 SVG + 用户手工实测」，如实告知用户，不得声称已测。
- 不同机器的 Office 版本、位数、插件状态差异很大，一次探测即可判定本机走哪条路；**不要反复重试同一调用**。

### 坐标系约定（写死，不再试错）

```
画布      width="1280" height="720" viewBox="0 0 1280 720"   ← 无单位
          （对应 PowerPoint 960×540 pt 的 16:9 页面）

换算      输出值 = 设计 pt 值 × 4/3

 设计 24   pt → 写 32
 设计 10.5 pt → 写 14
 设计 9.5  pt → 写 12.67
 设计 9    pt → 写 12
 左边界 60 pt → 写 80
```

**为什么**：PowerPoint 把 SVG 里无单位长度按 px（96dpi）解释，再折算 pt（72dpi），整体 ×0.75。写入 4/3 倍的数值，落地后正好回到设计值；且画布 1280 px 天然等于 13.333 in，插入即满页，无需手动设尺寸。

**禁止**：宽高写 `"960pt"`，或只写 `viewBox` 不给 `width`/`height`。

### 页面尺寸与坐标映射

- 先读取目标 PPT 模板实际的 `PageSetup.SlideWidth`、`SlideHeight`（单位 pt），以及 SVG 最终插入 PowerPoint 时的 x、y、width、height。
- 当前模板实测为 960×540 pt（对应上面的 1280×720 px 画布）；**换模板必须重新读取**，不得仅因同为 16:9 就沿用旧结论。
- 明确记录 SVG `viewBox` 到 PowerPoint 插入矩形的坐标映射比例。
- 插入态与转形态须位于相同的页面与插入矩形，**不得通过转形后手动拉伸或移动对象掩盖问题。**

### 字体与中英对齐

```
中文/正文   Microsoft YaHei
数字/拉丁   Arial      baseline 额外 +0.153 × 字号

实测度量（em = 1000）
  YaHei  ascent 1.0590   descent 0.2620
  Arial  ascent 0.9060   descent 0.2120
  差     0.1530 em  ← 拉丁下移量
```

**原因**：中文字体的 ascent 明显高于拉丁字体，PowerPoint 沿用一个文本框排拉丁字时，拉丁字母会整体偏高。

**校验方法**：同一行内，中文与数字写入的 `y` 应相差 `0.153 × 字号`。例：9.5 pt 表格行，中文 y=236.00、数字 y=237.45。

> 0.153 em 是 **YaHei + Arial** 这组字体的实测值；换字体必须重新测量，不能直接套用。

### 首要验收目标

同一个 SVG 在 PowerPoint 中的「**插入态**」，与执行「**转换为形状**」并取消选中后的「**转形态**」，应尽量保持相同的文字视觉大小、字宽、基线、换行和位置；两种状态都应接近已确认的 HTML。重点防止文字变大或变小后越界、串栏、覆盖图片或相互重叠。**不要仅凭浏览器、SVG 查看器或源码判断完成。**

### 文字与字体

- 文字须使用可编辑的 SVG 原生 `<text>`，明确设置 `font-family`、`font-size`、`font-weight`、`fill`、`x`/`y` 和必要的 `text-anchor`。
- 除 PowerPoint 外，不依赖额外字体、插件、网络字体或外部 CSS；优先使用目标系统常见字体，并说明跨设备字体替换可能带来的差异。
- 分别检查 SVG 插入态和转形态的可见字高、整行字宽、字距、基线、行距、换行，以及文本边界框（bounding box）。
- 区分「文字锚点坐标改变」和「字号或字体度量改变导致边界框扩大」：即使 x/y 没变，只要文字扩大并溢出，也视为未通过。
- 不要假定把 font-size 改为 pt、修改 SVG 根尺寸、或用 `transform:scale(...)` 就已解决；任何补偿都必须在模板实际尺寸下完成双态验证，并写回最终 SVG。

### 对象粒度与图片

- 一个标题、标签或正文视觉行尽量对应一个完整、可编辑的 `<text>`。
- 禁止逐字 `<text>`/`<tspan>`、逐字 x/y/dx/dy 坐标列表、文字转轮廓（text-to-path）；也不要把文字做成小图片或把整页截图封装成 SVG。
- `<tspan>` 仅在同一行确需局部改变颜色或字重时谨慎使用，并检查转形后是否拆框或位移。
- 每幅论文原图应是一个完整、内嵌的 `<image>`；不得外链、切片、平铺或拆成大量图片。
- 背景、边框和分隔线使用少量原生 SVG 形状。
- 确保 SVG 移动到其他目录后，论文原图仍能显示（内嵌，不依赖外部路径）。

### 几何校验五件套（代替肉眼）

没有视觉模型、或无法可靠看图时，必须跑完下面五项，**全部归零才算交付**：

| 校验 | 查什么 | 通行阈值 |
|---|---|---|
| 包围盒 | 每个文字按真实字体度量算 bbox，是否出界 | 左右边距 ≥ 30 pt |
| 两两重叠 | 任意两个文字 bbox 是否相交 | 重叠 ≤ 1.6 pt |
| 容器包含 | 文字是否溢出所属卡片底色框 | 溢出 ≤ 3 pt |
| 截断 | `maxlines` 是否吃掉正文 | 必须 0 处 |
| 压图 | 文字 bbox 是否压到 `<image>` | 必须 0 处 |

另加一步：**渲染后用 PDF 引擎回读每段文字的真实坐标**，复核一次出界与重叠（防止估算与渲染不一致）。

### PDF 抽取三条红线

1. **公式对象**：`get_text()` 遇到 `inline-eq-IEqNN` 之类占位符，说明那里是真公式，值取不到。涉及 ± 标准差、超参、学习率时，标「未取到」，**禁止猜值**。
2. **旋转表格**：若表格数值的 x 分布远多于 y，可能是 90° 排版，行列坐标互换。必须用「相对提升」等衍生行做交叉验算才能确认。
3. **矢量图**：`get_images()` 返回空不代表没有图——论文插图常为矢量绘制。按 caption 的 y 坐标反推图区带。

### 图裁切流程

```
1. 取该图 caption 的 y0 作为图区下界
2. 向上取到上一段正文的 y1 作为上界（宽容 8 pt）
3. 渲染 → 按非白像素自动裁白边
4. 若裁完内容仍贴边（边距 < 3 px）→ 说明被切断，扩大范围重裁
5. 缩放到「显示宽度 × 2」像素，base64 内嵌
```

### PowerPoint 实测与交付

- 按用户最终使用的方式将 SVG 插入目标模板；复制为两张相同幻灯片，一张保留 SVG 插入态，另一张执行「转换为形状」。
- 两张都取消选中后，在 PowerPoint 编辑画布中检查，并导出同分辨率预览进行对照。
- 逐页核对文字边界框、视觉字号、基线、右边界、段间距、图片位置及所有溢出和重叠；发现明显偏差，修改 SVG 源文件并重新测试，**而不是只移动临时 PPT 中的转形对象**。
- **校准目标**：同一文本的可见字高和整行宽度差异尽量不超过 5%，文字起点与基线偏差尽量不超过页面尺寸的 1%；任何文字不得越界或相互重叠。
- 交付时报告每页转形后的文本框、图片及其他形状数量，并列出仍无法消除的差异；不得出现正文逐字成框或同一论文原图分裂成大量图片。
- 多行正文以转换前后版式稳定、文字可编辑为优先。
- **不要把「SVG 源码中只有一个 `<text>`」等同于「转形后整段是一个 PowerPoint 文本框」。** 若纯 SVG 无法稳定得到整段单一原生 TextFrame，请明确说明，不要声称已实现。

### 交付后的收尾

- 把 SVG 一页一页插入 PPT 中，并点击「转换为形状」进行调试检查。
- **注意：这一步要使用 PowerPoint；WPS 兼容性不佳。**
- 导入之后需要简单进行字号和排版的调整。

## 附加交付（可选）：演讲稿

当用户需要配合 PPT 的**演讲稿**时，基于**已确认的页面内容**生成（不基于草稿，避免与最终页面对不上）。

### 先询问用户

1. **演讲总时长**（如 15 分钟）——决定全篇字数总量。
2. **每页大约时长 / 字数**——若用户没给，按「总时长 ÷ 页数」均分，并向用户说明这个分配。
3. **演讲风格**——如严谨学术、轻松通俗、答辩风格、组会汇报风格。

### 生成规则

- **按 PPT 页生成，一页对应一段**，段序与页序严格一致，每段标注「第 N 页 / 页标题」。
- 控制每段字数：中文口播约 **每分钟 220–260 字**，按用户给的每页时长换算；总额应与总时长一致。
- 每段**开头写衔接词/过渡句**，承接上一页、引出本页（如「讲完方法，我们来看它在实验上的表现……」）；最后一段做收束。
- 每段中的**重点内容加粗**（Markdown `**...**`），便于讲述时抓重点、也便于临场扫读。
- 先给一张**时长分配表**（页号 / 页标题 / 建议时长 / 目标字数），再逐页给讲稿正文。
- 只讲已确认页面上的内容，**不新增论文里没有的结论、数据、参数**。
- 严格遵守「论文已有结论」与「对我们工作的建议」的区分：建议类用「可考虑」「建议验证」「后续可探索」等措辞。
- 专业术语首次出现时，给一句口头解释，方便听众跟上。
- 若某页信息量不足以撑满预算时长，**如实说明并建议**（精简页数、合并页面或补充论据），不要灌水凑字数。
